# Security controls and deployment review

Implemented: Argon2id hashing; generic credential errors; short-lived signed JWTs; random refresh tokens stored as SHA-256 hashes; atomic refresh consumption/rotation; reuse revokes the session; logout and deactivation invalidate access through database session checks; HttpOnly cookies; configurable Secure and SameSite=Lax; session-bound CSRF headers and exact Origin checking; backend role and owner checks; input validation and sort whitelists; SQLAlchemy bound queries; audit entries without authentication secrets; private generated storage keys; bounded uploads and image/PDF signature validation; shared Redis throttling; safe attachment filenames; no-cache private API responses and security headers.

Production settings fail validation without HTTPS, secure cookies, Redis, PostgreSQL and S3 storage. The public deployment should expose one HTTPS origin. Backend proxy headers are disabled by default: client identity cannot be forged through arbitrary X-Forwarded-For. At an ingress configure a trusted proxy network explicitly if per-client IP throttling is required; account-based throttling remains independent.

The migration adds a PostgreSQL trigger rejecting audit UPDATE/DELETE. Use non-superuser runtime credentials without ownership/DDL rights, and a separate migration identity. Local Compose uses a development database owner and must not be exposed publicly as a production configuration.

Storage and PostgreSQL are separate transactional systems. Upload failures clean up uploaded objects where possible; cleanup failures log the generated object key, never credentials. `reconcile_storage` lists orphaned objects older than one day; deletion is explicit. Keep object retention and database backups coordinated.

Operational requirements before production: TLS/ingress and request size controls, backups and restore exercises, approved image digests and dependency lock updates, secret rotation, log retention, resource monitoring, private bucket IAM, database least privilege, browser QA and PostgreSQL concurrency verification. The compatible default CSP permits inline scripts and development eval; use deployment-specific nonce handling for a strict script policy. File signatures do not replace malware scanning. No invitation/email delivery or self-service password recovery is implemented: managers create initial employee credentials and the bootstrap creates the first manager interactively.
